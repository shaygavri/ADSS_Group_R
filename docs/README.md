## תיאור כללי

המערכת היא מערכת ניהול משולבת עבור רשת סופר-לי.
המערכת מאחדת מספר מודולים מרכזיים:

* מערכת עובדים וכוח אדם
* מערכת הובלות
* מערכת מלאי וספקים

בעת הכניסה למערכת, המשתמש מזין פרטי עובד. לאחר הזדהות, המערכת מזהה את סוג העובד ואת התפקידים שלו, ולפי זה מנתבת אותו למודול המתאים.

לדוגמה:

* עובד כוח אדם ינותב למערכת העובדים.
* מוביל / עובד הובלות ינותב למערכת ההובלות.
* עובד מלאי / ספקים ינותב למערכת המלאי והספקים.

## ניווט לפי תפקיד עובד

המערכת עובדת לפי הרשאות ותפקידים.

אם העובד הוא עובד רגיל, יוצג לו תפריט עובד רגיל.

אם העובד הוא מנהל כוח אדם, יוצג לו תפריט ניהול עובדים וכוח אדם.

אם העובד שייך לתחום ההובלות, המערכת תנתב אותו למערכת ההובלות.

אם העובד שייך לתחום מלאי וספקים, המערכת תנתב אותו למערכת המלאי והספקים.

## הזמנה עקב חוסר מלאי

כאשר מוצר יורד מתחת לרמת המלאי המינימלית, ניתן ליצור הזמנה עקב חוסר.

מוצר נחשב בחוסר כאשר:

```text
totalQuantity < minLimit
```

מהלך הפעולה:

```text
1. המשתמש נכנס לתפריט ספקים.
2. בוחר Handle Shortage Orders.
3. המערכת מציגה את כל המוצרים שיש להם חוסר במלאי.
4. המשתמש בוחר Product ID.
5. המערכת מחשבת כמה יחידות צריך להזמין.
6. המערכת פונה למערכת הספקים המדומה ומקבלת את ההצעה הטובה ביותר.
7. נוצרת הזמנה במצב DRAFT.
8. המערכת מציגה סיכום הזמנה.
9. המשתמש מאשר או מבטל את השליחה.
```

אם המשתמש מאשר:

```text
DRAFT → SENT
```

אם המשתמש לא מאשר, ההזמנה נשארת במצב:

```text
DRAFT
```

המלאי לא מתעדכן בזמן שליחת ההזמנה.
המלאי מתעדכן רק לאחר סימון ההזמנה כהתקבלה.

---

## סימון הזמנה כהתקבלה

בתפריט ספקים, בחירה באופציה:

```text
4. Mark Order As Received
```

מאפשרת להזין מזהה הזמנה.

אם ההזמנה קיימת ובסטטוס:

```text
SENT
```

המערכת:

```text
1. מוסיפה את הכמות שהוזמנה לכמות במחסן.
2. מעדכנת את הכמות הכוללת של המוצר.
3. משנה את סטטוס ההזמנה ל-RECEIVED.
```

כלומר:

```text
SENT → RECEIVED
```

---

## חוזה להזמנה תקופתית

הזמנה תקופתית עובדת כמו הוראת קבע.

לדוגמה:

```text
כל 10 לחודש להזמין 30 יחידות מהמוצר P001
```

חשוב להבדיל בין חוזה להזמנה תקופתית לבין הזמנה אמיתית.

חוזה תקופתי הוא רק כלל ששמור במערכת.
הוא עדיין לא הזמנה שנשלחה לספק.

כאשר מגיע הזמן להפעיל את החוזה, המערכת יוצרת ממנו הזמנה אמיתית מסוג:

```text
PERIODIC
```

---

## יצירת חוזה להזמנה תקופתית

בתפריט ספקים, בחירה באופציה:

```text
5. Create Periodic Order Contract
```

המשתמש מזין:

```text
Product ID
Quantity
Day Of Month
```

לדוגמה:

```text
Product ID: P001
Quantity: 30
Day Of Month: 10
```

המערכת שומרת חוזה תקופתי בטבלת `periodic_order_rules`.

החוזה כולל:

```text
Rule ID
Product ID
Quantity
Day Of Month
Next Delivery Date
Active
```

## הפעלת הזמנות תקופתיות

בתפריט ספקים, בחירה באופציה:

```text
6. Run Periodic Orders
```

גורמת למערכת לבדוק את כל החוזים התקופתיים הפעילים.

עבור כל חוזה, המערכת בודקת האם היום הוא יום אחד לפני תאריך האספקה הבא.

אם כן:

```text
1. המערכת יוצרת הזמנה אמיתית מסוג PERIODIC.
2. המערכת מקבלת הצעת מחיר מספק.
3. המערכת שולחת את ההזמנה לספק.
4. סטטוס ההזמנה משתנה ל-SENT.
5. תאריך האספקה הבא של החוזה מתקדם לחודש הבא.
```

אם מריצים את הפעולה שוב באותו יום, המערכת לא יוצרת הזמנה כפולה.

## ספריות ושכבות קוד שנעשה בהן שימוש

הפרויקט מחולק למספר ספריות ושכבות:

```text
PresentationLayer
```

אחראית על ממשק המשתמש, הדפסת תפריטים, קבלת קלט והצגת תוצאות.

```text
ServiceLayer
```

אחראית על תיאום הפעולות במערכת, הפעלת לוגיקה של מלאי, ספקים, הזמנות ומבצעים.

```text
DomainLayer
```

אחראית על אובייקטי הדומיין המרכזיים של המערכת, כגון מוצר, קטגוריה, מבצע, הזמנה ופריט הזמנה.

```text
Repository
```

אחראית על שמירה ושליפה של אובייקטים מהמערכת, ומפרידה בין הדומיין לבין שכבת הגישה למסד הנתונים.

```text
DAO
```

אחראית על פעולות SQL מול בסיס הנתונים.

```text
DTO
```

אחראית על העברת נתונים פשוטים בין שכבת ה־DAO לשכבת ה־Repository.

```text
Database
```

אחראית על פתיחת חיבור ל־SQLite, יצירת הטבלאות וטעינת נתוני דוגמה.

```text
SupplierIntegrationMock
```

אחראית על הדמיית מערכת ספקים חיצונית.

## הרצת הפרויקט

1. לפתוח את הפרויקט ב־IntelliJ IDEA.

3. להריץ Build לפרויקט.

```text
Main.java
```

5. להזין פרטי עובד.
6. המערכת תזהה את תפקיד העובד ותנתב אותו למודול המתאים.

## הערות חשובות

* המערכת מנתבת את העובד לפי התפקיד שהוגדר לו.
* מערכת הספקים היא Mock המדמה מערכת ספקים חיצונית.
* נתוני מלאי, קטגוריות, מבצעים, הזמנות וחוזי הזמנה תקופתית נשמרים ב־SQLite.
* הזמנות עקב חוסר נוצרות תחילה כטיוטה.
* מלאי מתעדכן רק לאחר סימון הזמנה כהתקבלה.
* חוזה הזמנה תקופתית אינו הזמנה אמיתית, אלא כלל שממנו נוצרת הזמנה תקופתית בפועל.
